Unlambda

No variables and no loops: only functions applied to functions.

By David Madore, 1999.

`r`````````````.H.e.l.l.o.,. .W.o.r.l.d.!i

What it is

Unlambda is a language of functions and nothing else. There are no variables, no numbers and no loops. A program is one expression, written in prefix form: a backtick means “apply the function after me to the one after that”. Everything is computed by applying functions to functions.

It is built from a handful of functions. k and s are the two combinators that, between them, can build any function; i returns what it is given. For output there is .x, which prints the character x when it is applied, and r, which prints a newline.

This site runs `, s, k, i, v, d, r and .x. The rest of the language (c, e, @, ?x and |) is not run here.

The functions used here

WrittenMeaning
`Apply the next expression to the one after it
iIdentity: gives back its argument
k`kx is a function that ignores its argument and gives back x
s```sxyz is ``xz`yz
.xPrint the character x, and give back the argument
rPrint a newline, and give back the argument
vGives back v, whatever it is applied to
dDelays the next expression until it is applied

Hello, World!

42 characters; it prints Hello, World!↵ in 14 steps, one for each backtick, which is each application. It reads left to right: apply .H to .e, which prints H and gives back .e; apply that to .l, which prints e; and so on to the final i. The last step, r, prints the newline.

How it runs

A smaller one, to show the combinators working: skk is the identity function, built from s and k alone. Applied to .a it gives back .a, and one more application to i prints the character. It prints a in 7 steps.

Seven applications to do what i does in one: that is the cost of building everything from s and k. The functions are never named, only applied.
